# E1 Platform foundations: stories

Status key: ✅ done in this epic · ⏭ moved to a later epic (reason given).

## F1.1 Launcher and service registry
- ✅ **S1 `ServiceSpec` and registry.** As a contributor, I add a service by writing one `ServiceSpec`.
  - *Acceptance:* `inkcast services` lists every built-in service. Third-party specs load from the `inkcast.services` entry point; a broken plug-in is logged and skipped.
  - *Design note:* specs are data (name, kind, routes, workers, public paths, needs). The launcher holds the only list of built-ins, so `libs/` stays service-agnostic.
- ✅ **S2 `INKCAST_APP_NAME`.** As an operator, I pick services by CamelCase name, or several comma-separated.
  - *Acceptance:* `All` is the default. `all|web|worker` still work. A lowercase or unknown name exits 78 with the list of valid names (`test_libs.ConfigGate`, `test_architecture.test_resolve_app_names`).
- ✅ **S3 `inkcast services`** prints name, full name, kind and summary.

## F1.2 Shared libraries
- ✅ **S1 Move shared code to `libs/`.** Old import paths stay as aliases to the same module objects, so plug-ins and scripts keep working.
- ✅ **S2 Split storage into domain repositories** (`identity`, `vault`, `posts`, `ledger`) over one `Database`. Ownership is documented in `libs/db/__init__.py` and ADR-0003.
- ✅ **S3 Architecture test.** `tests/test_architecture.py` fails on a libs → services import or a service → service import.

## F1.3 HTTP app factory
- ✅ **S1 Prefixes.** `INKCAST_PATH_PREFIX` = `/`, `auto` (`/<full-name>` per service) or an explicit path. Probes always answer at the root (`test_libs.Prefixes`).
- ✅ **S2 Probes and errors in one place.** `/livez`, `/readyz` (store, scheduler tick, per-service checks) and `/healthz`. REST errors are RFC 9457 `application/problem+json`, keeping `error`/`message`.
- ✅ **S3 OpenAPI.** One public document (`libs/contracts/openapi.py`); each operation is tagged `x-inkcast-service` and `x-inkcast-scope`. Docs pages stay vendored and CSP-strict.

## F1.4 Config and secrets
- ✅ **S1 Config gate.** `Config.validate(needs)` checks only what the services in the process need. The launcher exits 78 before serving (`test_bad_config_exits_78_before_serving`).
- ✅ **S2 `SecretValue`, `SecretsProvider`, Redactor.** Secrets print as `***`; log lines are redacted; the provider has TTL with jitter, single-flight and stale-on-error (`test_libs.Secrets`, `test_libs.Logging`). The reference secrets design is completed in this epic's review patches (see `review.md`).
- ✅ **S3 One public URL.** Every link Inkcast returns derives from `INKCAST_PUBLIC_URL`.

## F1.5 Gateway
- ✅ **S1 Built-in Gateway** routes by the shared table, passes `Host` through, sets `X-Forwarded-*`, and reports a missing or unreachable upstream as a 502 problem naming the variable to set.
- ✅ **S2 `components/gateway-api`.** HTTPRoutes are generated from the route table; a test checks they agree.
  - ⏭ An OpenShift per-path Routes component isn't needed: the built-in Gateway behind the existing single Route covers OpenShift. Clusters on OpenShift 4.19+ can use `gateway-api`.
- ✅ **S3 `components/split-services`.** One Deployment and Service per service, generated by `scripts/gen-manifests.py`, plus an internal NetworkPolicy (Gateway → services only).

## F1.6 CI
- ✅ **S1 kind, split.** CI deploys `overlays/ci-split` next to the single-pod overlay and smoke-tests the public paths through the Gateway.
- ✅ **S2 e2e twice.** The whole end-to-end suite also runs split behind the Gateway (`test_split_mode.SplitServices`, `test_git_publishing.GitPublishingSplit`).
- ⏭ **S3 web job.** This arrives with `web/` in E4.

## F1.7 Docs
- ✅ ADRs 0001–0005, the definition of done, the contributor map, and the epic docs.
- ✅ Backlog-as-code: `docs/backlog/*.yaml` and `scripts/backlog/file.py`.
